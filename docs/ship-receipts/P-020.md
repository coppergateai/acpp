## Outcome

- `@acpp/db`: `ConnectionStore` with one GitHub connection per workspace and server-side credential vault keyed by `credentialRef`
- `@acpp/github`: real GitHub REST HTTP for `repos.metadata.read` and `issues.comment` (injectable `fetch` for tests)
- `@acpp/api`: `POST /v1/workspaces/{id}/connections/github`, `GET …/connections`, `POST /v1/github/actions/execute` (authz gate then execute)
- Tests: connection store isolation, GitHub HTTP mocks, API two-agent scoped execution on one connection
- Docs: `docs/protocol/connections.md`, `docs/CHANGELOG.md`

## Invariants

- Connection tokens never appear in list/connect response bodies exposed to agents.
- Unauthorized or wrong-scope agents receive policy denial before GitHub HTTP.
- Same workspace connection serves multiple agents with different grants (Use Case D).
